How the names are built

Each mnemonic is a few letters taken from English words, plus pieces that repeat. Learn the pieces and most names read themselves: ldrsb = LoaD Register Signed Byte.

Operands in the forms: rd = Destination register (gets the result), rs = Source register, rn = first operand or the base of an address, rm = second operand register, #imm = IMMediate (a constant inside the instruction).

Registers: r0–r7 are the "low" ones, which almost every instruction can use; r8–r12 only with mov, add, cmp. objdump names some by their role: sl = r10, fp = r11, ip = r12, sp = r13 (stack pointer), lr = r14 (link register: the return address), pc = r15 (program counter).

Flags, set by the …s instructions and cmp: N result Negative, Z result Zero, C Carry (unsigned overflow; after a compare, "no borrow"), V oVerflow (signed).

Calling convention

What every function agrees on, so any caller can call any callee. ARM publishes the rule (the Procedure Call Standard, APCS back then); what counts here is how agbcc applies it, set in agbcc-src/gcc_arm/config/arm/thumb.h (CALL_USED_REGISTERS, FIXED_REGISTERS, FUNCTION_ARG_REGNO_P, FUNCTION_VALUE). The game was built with the same compiler, so its functions follow it too: whatever is in r0–r3 on entry is the arguments.

r0–r3Arguments 1–4; the result comes back in r0 (r0+r1 for 64 bits). A call may overwrite them: caller-saved.
r4–r7Survive calls: callee-saved. A function that uses them saves them first (push {r4, lr}) and restores them before returning.
r8–slAlso callee-saved. agbcc only parks values there (mov r8, r4) when r4–r7 run out.
fp (r11)Reserved; agbcc never hands it out.
ip (r12)Scratch; a call may overwrite it.
sp, lr, pcStack pointer, return address (set by bl), program counter.
5th arg onOn the stack: the caller stores them at [sp, #0], [sp, #4]… right before the bl.
struct resultReturned in r0 only if it fits in 4 bytes and has a single field (bit-fields aside). Otherwise, even struct { s16 col, row; }, the caller passes a hidden pointer in r0, the real arguments shift to r1…, and the callee writes the result there (thumb_return_in_memory, thumb.c:1426).

Why pop {r1}; bx r1 and not pop {pc}: the saved lr comes back into a free scratch register and bx returns through it, so the caller may be ARM or Thumb (bit 0 of the address). Which scratch register depends on which one isn't holding the result.

How to look

-da: dumps per pass

Writes the RTL (agbcc's internal code, one (insn N …) per instruction) after every pass to FILE.c.PASS. Diff two neighbours to see what one pass did.

.rtl .jump .cse .addressof .gcse .loop .cse2 .flow .combine .regmove .lreg .greg .jump2 .mach: each is a pass below. .rtl is the output of expand; .addressof puts back in registers variables whose &var turned out unneeded; .lreg/.greg are local and global alloc (.greg includes reload); .mach is thumb_reorg.

Single letters: r j s F G L t f c N l g J M.

-dp: insn numbers in the asm

Each asm line gets its insn number (@ 151), to find it in the dumps.

-fno-X: turn a pass off

If the diff changes, that pass is involved. Each card lists the flags that exist; many passes have none.

Before register allocation

1Expand: C → RTL stmt.c expr.c expmed.c fold-const.c

EXPAND the C tree into RTL: Register Transfer Language

Turns the C tree into RTL. Many shapes are decided here, before any optimization.

  • switch: a jump table only with at least 5 cases and a value range of at most 10 × the case count (stmt.c:4926). Otherwise a tree of compares.
  • Constant folding: hp + 2 + 3 → hp + 5, count * 8 → shift, comparisons simplified.
  • Multiply / divide by constants (expmed.c): shifts and adds instead of mul; signed divide by a power of 2 adds a fix-up for negatives.
  • Types: u8/s8/u16 get widened with lsl #24; lsr #24 (asr if signed). The type of a local, parameter or cast decides which shifts appear and where.
Levers
Types, casts, switch vs if chain, how an expression is split into statements.

2jump jump.c

JUMP optimization

Cleans up branches. Runs again after cse, gcse and loop, all without cross-jumping (that one is only in jump2).

  • Loop inversion (duplicate_loop_exit_test, jump.c:2424): while (cond) body becomes if (cond) do body while (cond). That's why loops test before entering and again at the bottom.
  • Jumps to jumps redirected; unreachable code deleted; an if with an empty arm is flipped.
  • At -O2 also delete_null_pointer_checks and merge_blocks (flow.c:3811).
Levers
for vs while vs do vs goto (CLAUDE.md: loops can need gotos).

3cse cse.c + thread_jumps

Common Subexpression Elimination

Common subexpression elimination inside a stretch of code: a value computed twice is computed once and reused; a load from the same address is reused while nothing could have changed it. thread_jumps sends a branch whose outcome is already known straight to its target.

volatile tells the compiler a value can change behind its back (a hardware register like REG_VCOUNT, or a variable an interrupt writes). So every read and write in the C happens in the asm, in that order: nothing is reused or dropped. In a decomp it's a lever: the original may not have used it, but it reproduces a second load the original had for another reason.

In the asm
A field read once though the C reads it twice; a constant kept in a register.
Levers
volatile to force each read; recomputing vs storing in a local.
Flags
-fno-cse-follow-jumps -fno-cse-skip-blocks -fno-thread-jumps

4gcse gcse.c

Global Common Subexpression Elimination (global = across blocks)

Global cse over the whole function, up to MAX_PASSES rounds (gcse.c:730). Each round:

  • cprop (Copy/constant PROPagation): copy and constant propagation (hp = 5; … max = hp → max = 5).
  • PRE (Partial Redundancy Elimination): if a value is computed on some paths and again after they meet, it computes it on the missing paths too, so the later one becomes a reuse. Creates new pseudos. guess their stack slots follow its hash table order.
  • Code hoisting only with -Os (gcse.c:767), so not here.
In the asm
A computation moved into the branches before a merge point, or moved earlier.
Seen here
A dead check like if (dh1 == 0) cost1 = 0; gives PRE a second computation to unify, so it moves h1 - h0 (BuildReachMap).
Flags
-fno-gcse

5loop loop.c, twice (-frerun-loop-opt)

LOOP optimization

  • Invariant motion: a computation that doesn't change inside the loop moves before it.
  • Strength reduction: i * 12 inside the loop becomes a variable that grows by 12.
  • No unrolling (-funroll-loops not set).
In the asm
Values computed once before the loop, extra counters, shifted counters in stack slots.
Flags
-fno-strength-reduce -fno-rerun-loop-opt

10Register allocation local-alloc.c, then global.c

register ALLOCation; dumps lreg = Local REG, greg = Global REG

Each value the C needs (a "pseudo") gets a hard register, or none, and then it lives on the stack.

  • local-alloc: values that live inside one basic block. Priority floor_log2(refs) × refs × size / lifetime (local-alloc.c:1435).
  • global: the rest, by floor_log2(refs) × refs / lifetime (global.c:614). A tie goes to the lower pseudo number (global.c:630), so declaration order matters.
  • Values that live across a call want r4–r7 (the callee keeps them); r0–r3 are clobbered by calls. -fcaller-saves can keep them in r0–r3 and save them around the call.
In the asm
Which value is in r4 vs r5; who ends up on the stack.
Levers
Declaration order; number of uses (an extra use raises priority); lifetimes (moving a use earlier or later); splitting a variable in two.

11reload reload1.c reload.c

RELOAD values into the registers each instruction accepts

Fixes everything the Thumb can't do as allocated: values without a register are loaded into a temporary ("reload register") around each use; stack slots are assigned.

  • Rotation: temporaries are taken round-robin from the spill registers (r0–r2 in BuildReachMap; the set varies per function), starting after the last one picked (last_spill_reg, reset per function at reload1.c:817, picked at reload1.c:5197). Busy registers are skipped.
  • A temporary whose register is already fixed (reload1.c:5769) or reused from before (inheritance) doesn't advance the rotation.
  • Stack slots: assigned in pseudo order; the Thumb frame grows upward (thumb.h:633).
In the asm
ldr rX, [sp, #N] right before a use; the same [sp, #N] loaded into r1, then r2, then r0.
If
The rotation is off by one with identical asm before it: see jump2.
Tools
RLDBG=1, scripts/why.sh

After reload

These run after registers are fixed, so anything they delete already left its mark on the allocation.

13jump2 + cross-jumping jump.c, called at toplev.c:3143

JUMP optimization, run 2

The last jump pass, the only one with cross-jumping. Two blocks that end in the same instructions and jump to the same place are merged. Going top to bottom, the block it is looking at deletes its own copy and jumps into the other one (jump.c:1970, do_cross_jump at jump.c:2836), so the lower copy survives. Also deletes moves from a register to itself.

Because it runs after reload, the deleted copy already took a step of the reload rotation.

14thumb_reorg thumb.c:352

THUMB REORGanization: the machine-dependent pass (dump mach = MACHine)

Puts constants that don't fit in an instruction into literal pools after a barrier (ldr r0, =0x… → ldr r0, [pc, #N] + .word). Decides where pools and alignment padding (.short 0x0000) go.
